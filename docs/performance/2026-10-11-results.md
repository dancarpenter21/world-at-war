# Durable performance checkpoint — 2026-10-11

All 18 reference runs completed: one baseline matrix and two optimized matrices,
each containing regional, global and mixed profiles in both storage modes.
Every run is valid, with no client errors, failed durable operations or dropped
trace samples. Regional full-cycle and all sampled reconnect budgets pass.

## Reference and method

Reference hardware: AMD Ryzen 7 9800X3D 8-Core Processor, 16 logical CPUs, WSL
6.6.87.2-microsoft-standard-WSL2; rustc 1.96.0 (ac68faa20 2026-05-25), Node v24.15.0.
Baseline revision: `b3fc197e0401c2ac83188b8ee14e0c1241fa8c27`. Optimized revision: `5f07ba0a618fb32b35f2f0e17f5869a63dab1535`.
Pinned c3mesh: `2f13199e665806b5d0ac0f0f4db07eb436e0a008`.
PostgreSQL image: `postgres@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24`.
Each durable run uses a fresh Docker named volume, with fsync, synchronous commit
and full-page writes enabled. Resolved image IDs, binary hashes, scenario/catalog
checksums, role assignments, toolchain and clock metadata accompany each result.

Seed 12787750; 60 seconds warmup and 300 measured seconds per profile.
Regional has 11 players/one game; global has 13/one; mixed has 50/five.
Runs are sequential without competing builds. The final repetition reverses
storage-mode order. All are separate short runs; no long soak was executed.
Setup request timing and history lengths vary between runs. These are observed
reference-workload results, not identical event streams or universal speedups.

Full-cycle timing includes backups, lease processing, all game advances, boundary
encoding/hashing, PostgreSQL commit and post-commit bookkeeping. Gate/lock waits
are separate, and scheduled-to-committed latency includes them. Shared transaction
costs are reported for the whole server cycle. Per-game processing remains available
but excludes persistence. The standalone regional budget uses the full cycle.

Client timing uses measurement version 3: epoch-shaped timestamps anchored to
monotonic process time. Four initial version 2 attempts failed analysis after WSL
wall-clock corrections produced negative stream gaps. Their [original results](2026-10-11/initial-attempts.json) remain excluded from acceptance.

## Storage work and resource growth

The writer prepares SQL once per connection, batches memberships, seats and
archive writes, and avoids new tuple versions for unchanged memberships/seats.
Ordinary ticks no longer submit unused snapshot arguments. Checkpoints retain
complete snapshots and the previous cadence; every tick still encodes and hashes
complete canonical state. Lifecycle details are encoded without copying discarded
message bodies and byte arrays. Transaction, fencing and rollback semantics remain.

runs do not establish bounded application memory or an archival retention policy.
RSS did not consistently improve and regional optimized runs ended above baseline.

## Correctness and remaining acceptance

All 18 raw traces were independently reanalyzed; their metrics, committed-game
progress and trace footers match the saved summaries.

All four current-baseline core projection hashes match after optimization across
both repeats. See [before](2026-10-11/core-before.json) and
[after](2026-10-11/core-after.json). The current baseline uses the merged persistence
dependency and serialization settings; this report does not claim compatibility
with every older checkpoint hash.

Validation includes 206 fast workspace Rust tests at the instrumentation checkpoint,
96 server tests after the storage changes, nine PostgreSQL integration tests, ten
harness tests including real-container interruption cleanup, strict workspace
Clippy and formatting, 45 frontend tests, the production web build and the
persistence browser crash-recovery test. Database tests verify unchanged tuple
versions, recovery from the previous checkpoint, zero ordinary-tick snapshot
submission, injected commit latency/failure, archive fidelity, revocation and fencing.

CI exercises both storage modes with short loads and checks validity rather than
reference-hardware timing. No new hosted CI or publication result is claimed here.
Long-soak acceptance, roadmap-scale workloads, browser rendering, delta bandwidth,
full packet/fragment audit, retention policy and interactive replay remain open.

## Reproduce and artifacts

Build a release server and verify the dependency pin, then run each profile in
each storage mode with a new output directory:

```sh
sh scripts/setup-c3mesh.sh --verify-only
cargo build --release --locked -p world-at-war-server
node web/scripts/performance-server.mjs --storage postgres --profile mixed \
  --warmup 60 --duration 300 --reconnect-every 60 \
  --postgres-image postgres@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24 \
  --output tmp/performance/durable-mixed
```

Compact artifacts preserve metadata, every metric summary, trace-footer counts,
first/last/peak resource measurements and retention bounds. Raw JSONL traces
remain ignored local output under `tmp/performance/`; CI uploads equivalent raw
evidence. See [load-testing definitions](LOAD_TESTING.md).
