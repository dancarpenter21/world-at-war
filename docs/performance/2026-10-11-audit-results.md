# Communications audit and retention checkpoint — 2026-10-11

The communications metadata audit and optional archive retention implementation
adds terminal-local history without changing canonical simulation projections.
Functional validation passes; regional PostgreSQL performance acceptance remains
open because the measured maximum committed cycle exceeds its budget.
This checkpoint measures its full-server cost against the
[preceding persistence checkpoint](2026-10-11-results.md).

## Method and reproducibility

Six independent full-server profiles use 60 seconds of warmup followed by
300 seconds of measurement, seed 12787750 and reconnects every 60 seconds.
Regional uses one game and 11 clients; global uses one game and four clients;
mixed uses five games and 50 clients. The protocol exercises HTTP state/planning
and 1 Hz full-snapshot WebSockets; it does not measure browser rendering.
Archive retention is disabled in these six runs. A separate 75-second regional
PostgreSQL smoke uses one client and one-day retention to exercise maintenance.

The host is WSL2 Linux x86_64 on an AMD Ryzen 7 9800X3D with 16 logical CPUs,
Rust 1.96.0 and Node 24.15.0. PostgreSQL uses the pinned image
`postgres@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24`.
The c3mesh source pin remains `2f13199e665806b5d0ac0f0f4db07eb436e0a008`.
These measurements use an uncommitted working tree based on
`764523c523c33955f89b691064f013fdc3cce844`; source-file and release-binary hashes
are retained with the artifacts. No new commit is implied by that base revision.

Regional PostgreSQL passes the 250 ms p95 limit but **fails the 1,000 ms
maximum-cycle limit**. Its two largest successful persistence commits took
2,241 and 1,547 ms near the end of measurement. The available trace attributes
the delay to commits, but does not establish a PostgreSQL checkpoint or host-I/O
root cause. All sampled reconnects stay below the 3,000 ms budget. The harness
has no standalone global/mixed cycle budget; those timings are reported rather
than certified against an invented threshold.

The regional and mixed workloads generate substantial communications traffic.
Their durable p95 increases require follow-up storage/write-path optimization
before performance acceptance. The global workload generated only 19 audit
observations, so its timing does not represent a busy communications workload.
Independent stateful runs vary; these comparisons are not identical event-stream
replays and do not establish a precise causal overhead percentage.

Growth is measured from the first to last resource sample within each measured
window. Database totals include simulation journals, snapshots, indexes and
archives. WAL is the cumulative generated byte counter, not retained disk size.
Private metadata bytes count encoded captured events; role-projection copies,
SQL/index overhead and WAL are additional. RSS reflects the entire server and
cannot isolate audit allocations. Compact artifacts retain first/last/peak
samples; raw traces retain each sample.

Volatile audit storage is bounded to 10,000 projected observations per game,
with role-local truncation reported after eviction. Durable-event totals are zero
in volatile summaries because that counter measures committed archive writes.
Default indefinite PostgreSQL retention permits archive growth.

The [75-second retention smoke](2026-10-11-audit/retention-smoke.json) passes its
regional timing budget (196.6 ms p95, 321.4 ms maximum). Scheduled maintenance
runs successfully with zero eligible/deleted records, as expected for fresh data.
Aged-data deletion and multi-batch draining are verified by database fixtures.

## Validation and limits

Validation passed 213 fast workspace Rust tests, 13 PostgreSQL integration tests,
45 frontend unit tests, 61 Chromium browser tests and 14 performance harness
tests, including container interruption cleanup. Formatting, strict workspace
Clippy, the frontend production build and Rust 1.89 compatibility checking pass.
The core benchmark uses 30 warmup ticks, 120 measured ticks and two repeats;
all four scenario/repeat projection hashes match the preceding core baseline.

Database fixtures verify schema 1–5 migration, recovery without audit duplication,
transaction rollback on required audit failure, role-local cursor floors,
pending-traffic and shared-body protection, cross-archive age checks and atomic
cleanup failure. A synthetic aged archive verifies that automatic maintenance
continues across multiple bounded transactions while a paused game's canonical
state remains unchanged. The smoke run exercises scheduled maintenance against
fresh records; it does not substitute for aged-data deletion coverage.

No long soak was run. Short profiles and bounded volatile history do not establish
long-term memory stability or a bounded database with indefinite retention.
Roadmap-scale loads, browser/GPU performance, delta bandwidth, raw packet payload
export and interactive historical replay remain separate work.
