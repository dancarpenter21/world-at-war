## Sustained load

The [one-hour mixed-profile run](2026-10-09/soak.json) completed with 50 players
across five games: 3,600 measured seconds, 1,032,229 trace records, zero dropped
records and no client errors. Regional tick p95 was 7.8–9.1 ms; the worst
regional tick was 50.08 ms. All 50 clients reconnected within budget (maximum
118.94 ms). Reanalysis of the original trace reproduces every reported metric.

Server RSS grew from **158.09 to 2,603.69 MiB** over the measured hour. Passing
timing and reconnect checks does not resolve this retention problem or establish
24-hour stability. This run is the pre-compaction memory baseline.

## Follow-up work and limits

1. Profile memory retention before extending soak duration or increasing scenario
   scale. The simulation appends receiver-interference snapshots every tick;
   c3mesh retains these in per-device time histories. Completed-message IDs,
   authority records, intent receipts and network-message histories are also
   retained. Measure their contributions and define retention/compaction rules
   that preserve in-flight packet semantics, idempotency and future replay.
2. Reduce repeated full-projection work and evaluate incremental delivery.
   Global HTTP state projections are about 684 KB uncompressed and are built
   for each polling client, alongside network stream snapshots. Measure a
   future delta protocol before claiming the roadmap's 100 KB/s delta budget
   or 20 Hz delivery target.
3. Preserve per-game lock and scheduling measurements when testing higher
   concurrency. The current process serializes games and projections through
   a shared lock; this run establishes evidence for the existing workload.
4. Continue with durable accounts, game/lease persistence and packet audit,
   followed by deterministic recovery/replay. The 1,000-platform and
   10,000-background-object/track workloads and 24-hour release soak remain open.

See [load-testing instructions](LOAD_TESTING.md) for exact profiles, commands,
metric definitions and acceptance rules. These clients exercise the real HTTP
and WebSocket server with local catalog fixtures; they do not render Cesium or
measure WAN latency. Fifty distinct guests occupy five games, not one scenario.

Validation before reference measurements: 199 workspace Rust tests, strict
Clippy, formatting, 45 frontend tests, the production web build, four harness
tests (including interruption cleanup), and 34 selected authentication,
observer and session browser regressions passed. A two-minute 50-player smoke
also passed with lease renewals and 15 reconnects. The CI workflow was added;
these are local results, not a claim that hosted CI has run.
